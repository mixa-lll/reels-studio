# Как устроено

## Код

| Папка | Что внутри |
|---|---|
| `bot/` | Телеграм ↔ Claude: приём сообщений, очередь, прогресс, меню, команда (`members.mjs`). Node 22, без зависимостей |
| `web/` | веб-студия: `server.mjs` (HTTP API, чаты, версии, хранение, доступ), `index.html` (интерфейс), `send.mjs` (замена `bot/send.mjs` для студии) |
| `REELS.md` | как агент делает рилсы — общий для бота и студии |
| `template/` | стартовый проект Remotion, копируется в каждый рилс |
| `scripts/` | новый рилс, рендер с прогрессом, громкость, бит |
| `starter/` | заготовка нового проекта |
| `test/` | `npm test` — самопроверка бота на поддельном Телеграме |
| `docs/` | сайт установки (GitHub Pages) |
| `handbook/` | справочник проекта |

Данные, не в git: `projects/<проект>/` (бриф, идеи, PLAYBOOK, рилсы, входящие), `data/` (состояние бота, логи, `shared/access.json` — люди и приглашения), `web/data/` (чаты студии), `.env` (ключи).

## Как работает студия

- Каждый выпуск — свой сеанс Claude (`claude -p --resume`), чат хранится в `web/data/chats/<проект>/<выпуск>.jsonl`.
- Агент студии работает по списку разрешений (`ALLOWED` в `server.mjs`), а не «без вопросов»: файлы, поиск в интернете, `node scripts/*.mjs` и свой `send.mjs`. Свои данные и список доступа он читать не может (`DENIED`).
- Агент говорит со страницей через `web/send.mjs` → `web/data/events.jsonl` → поток событий на страницу.
- Хранение версий (`bot/storage.mjs`): в работе — две последние версии целиком, старше — кадр и снимок кода проекта; мастер на текущей версии или рилс принят — только последняя. Корзина студии `.trash/` уходит в Cloudflare R2 (`bot/cloud.mjs`, 30 дней), медиа и исходники упакованных рилсов — в облачный архив насовсем; без ключей `R2_*` корзина лежит на диске 30 дней. Старую папку целиком — `node scripts/cloud-archive.mjs <папка>`.
- Выпуск — четыре вкладки этапов (`#/reel/<id>/script|materials|edit|publish`, плюс `compare`). Сцены и подписи агент ведёт в файлах рилса: `scenes.json` (таймкод, название, что на экране, текст, звук, что нужно, что есть, статус) и `publish.json` (подписи по площадкам, проверка перед выкладкой). Нет файлов — вкладки показывают README и кнопку «попросить Claude». Сценарий по смысловым блокам — `script.json` (`web/script.mjs`): шаги «1 · Текст» (блоки, порядок, утверждение, варианты «Взять») и «2 · Вид» (что на экране на каждом блоке, на каких словах); чат на этом этапе встаёт внутрь этапа, выбранный блок или фраза — чипом в поле ввода (`chatBox().pin`), суфлёр — на весь экран с нахлёстом соседних фраз, с рилсом ещё и снимает: дубль уходит в `sources/take-<блок>-<n>` и в `takes` блока, лучший отмечается. «Материалы» показывают «Что снять» из блоков и вида; «Отдать на съёмку» делает задание в мини-приложение (строка текста = блок = фраза).
- Выкладка: `POST /api/publish` кладёт пакет (видео, обложка, подпись, время) в `outbox.json` рядом со списком людей; бот (`bot/outbox.mjs`) раз в 30 с отправляет созревшие пакеты в Телеграм тому, кто планировал (или владельцу). На стенде бота нет — там пакеты только копятся.
- Роли (`bot/roles.mjs`): `role = editor | member`, флаги `isOwner`, `deputyUntil` (редактор до даты включительно), `onCamera`, `web` (участнику открыт веб), `groups`. Старые owner/viewer/author читаются как новые. Редактор (и замещающий) видит всю студию и ведёт «Настройки › Команда»; участник в вебе — только «Мои задания», «Скинуть», «Мои материалы» (`/api/member`), в боте — диалог «скинуть материал» (`bot/author.mjs`). Всё присланное — в `inbox/authors.jsonl`, редакторам — «Входящие» (с двух человек).
- Несколько компьютеров одного владельца (`DEVICE_NAME` + `RELAY_NODE`, #142): у каждого своя студия за одним адресом (relay выбирает по cookie `device`, `relay/README.md`). Проект общий: лёгкая часть — git-репозиторий самого проекта, студия синхронизирует его раз в минуту и после правок (`bot/sync.mjs`); `sources/`, `versions/`, `project/public/` рилса — в `files.json` с хешами, файлы в R2 (`<проект>/media/<sha256>`), докачка при открытии. Рилс держит одно устройство (`files.json.holder`), Claude, рендер и чистка по нему — только там. Учёт на компьютере — `<проект>/.sync/` (не в git).
- Люди, приглашения, сессии — `data/shared/access.json`; его же читает бот (`REELS_MEMBERS`), поэтому приглашение работает и в Телеграме, и в вебе.

## Сервер

- Ubuntu 24.04, Амстердам. Бот — служба `reels-bot` (пользователь `reels`), студия — `reels-web` (пользователь `webdemo`, пишет только в папку проектов), HTTPS — именованный туннель Cloudflare `reels-tunnel` (`/etc/cloudflared/reels.yml`): `reels.mygudauri.org` → студия :8080, `stage-reels.mygudauri.org` → стенд :8081. Адреса постоянные.
- Код — git-копия этого репозитория в `/home/reels/reels-bot`. Секреты бота — `/etc/reels-bot/bot.env`, студии — `/home/webdemo/env`.
- Выкладка: ветка `prod` на GitHub. Таймер `reels-prod-watch` раз в 2 минуты видит, что она сдвинулась, и запускает `reels-deploy`: забирает `prod`, ставит зависимости, перезапускает студию сразу, а бота — когда он закончит текущую задачу. Откат — сдвинуть `prod` на прошлый коммит. Пока в студии работает Claude или идёт рендер, выкладка ждёт (перезапуск студии их убил бы) и пробует снова через 2 минуты; вручную — `REELS_DEPLOY_FORCE=1 reels-deploy`.

## Общий стенд

- Тот же сервер, отдельный пользователь `staging` (не видит бота владельца, его ключи и студию). Код — `/home/staging/reels-studio`, демо-проект — копия брифа, правил и одного готового рилса.
- Служба `reels-stage` на `127.0.0.1:8081`, снаружи — https://stage-reels.mygudauri.org, ключ входа — в `/home/staging/env` (первый вход по `?k=`, дальше браузер помнит).
- Таймер `reels-stage-update` раз в 2 минуты забирает `main` и перезапускает стенд — но не пока на стенде работает Claude или идёт рендер (перезапуск убил бы их); тогда ждёт следующей попытки: всё слитое видно на стенде через пару минут, без участия владельца.
- Мини-приложение «Съёмка» на стенде: https://stage-reels.mygudauri.org/app (тестовый бот, `TELEGRAM_BOT_TOKEN` и `MINIAPP_OWNERS` в `/home/staging/env`).
- Агент стенда работает на подписке владельца, поэтому тяжёлые рендеры лучше гонять у себя.
