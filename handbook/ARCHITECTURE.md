# Как устроено

## Код

| Папка | Что внутри |
|---|---|
| `bot/` | Телеграм ↔ Claude: приём сообщений, очередь, прогресс, меню, команда (`members.mjs`). Node 22, без зависимостей |
| `web/` | веб-студия: `server.mjs` (HTTP API, чаты, версии, хранение, доступ), `index.html` (интерфейс), `send.mjs` (замена `bot/send.mjs` для студии) |
| `REELS.md` | как агент делает рилсы — общий для бота и студии |
| `template/` | стартовый проект Remotion, копируется в каждый рилс |
| `scripts/` | новый рилс, рендер с прогрессом, громкость, бит |
| `starter/` | заготовка нового проекта |
| `test/` | `npm test` — самопроверка бота на поддельном Телеграме |
| `docs/` | сайт установки (GitHub Pages) |
| `handbook/` | справочник проекта |

Данные, не в git: `projects/<проект>/` (бриф, идеи, PLAYBOOK, рилсы, входящие), `data/` (состояние бота, логи, `shared/access.json` — люди и приглашения), `web/data/` (чаты студии), `.env` (ключи).

## Как работает студия

- Каждый выпуск — свой сеанс Claude (`claude -p --resume`), чат хранится в `web/data/chats/<проект>/<выпуск>.jsonl`.
- Агент студии работает по списку разрешений (`ALLOWED` в `server.mjs`), а не «без вопросов»: файлы, поиск в интернете, `node scripts/*.mjs` и свой `send.mjs`. Свои данные и список доступа он читать не может (`DENIED`).
- Агент говорит со страницей через `web/send.mjs` → `web/data/events.jsonl` → поток событий на страницу.
- Хранение версий: текущая целиком, прошлая — лёгкая копия, старше — кадр и снимок кода проекта (`retain()`).
- Люди, приглашения, сессии — `data/shared/access.json`; его же читает бот (`REELS_MEMBERS`), поэтому приглашение работает и в Телеграме, и в вебе.

## Сервер

- Ubuntu 24.04, Амстердам. Бот — служба `reels-bot` (пользователь `reels`), студия — `reels-web` (пользователь `webdemo`, пишет только в папку проектов), HTTPS — именованный туннель Cloudflare `reels-tunnel` (`/etc/cloudflared/reels.yml`): `reels.mygudauri.org` → студия :8080, `stage-reels.mygudauri.org` → стенд :8081. Адреса постоянные.
- Код — git-копия этого репозитория в `/home/reels/reels-bot`. Секреты бота — `/etc/reels-bot/bot.env`, студии — `/home/webdemo/env`.
- Выкладка: ветка `prod` на GitHub. Таймер `reels-prod-watch` раз в 2 минуты видит, что она сдвинулась, и запускает `reels-deploy`: забирает `prod`, ставит зависимости, перезапускает студию сразу, а бота — когда он закончит текущую задачу. Откат — сдвинуть `prod` на прошлый коммит.

## Общий стенд

- Тот же сервер, отдельный пользователь `staging` (не видит бота владельца, его ключи и студию). Код — `/home/staging/reels-studio`, демо-проект — копия брифа, правил и одного готового рилса.
- Служба `reels-stage` на `127.0.0.1:8081`, снаружи — https://stage-reels.mygudauri.org, ключ входа — в `/home/staging/env` (первый вход по `?k=`, дальше браузер помнит).
- Таймер `reels-stage-update` раз в 2 минуты забирает `main` и перезапускает стенд: всё слитое видно на стенде через пару минут, без участия владельца.
- Агент стенда работает на подписке владельца, поэтому тяжёлые рендеры лучше гонять у себя.
