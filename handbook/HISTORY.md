# История: что придумали и почему

Выжимка из чатов владельца с Claude (октябрь 2026). Читать один раз при входе в проект, чтобы не предлагать уже отброшенное. Решения коротко — в `DECISIONS.md`, продукт — в `PRODUCT.md`.

## Как появился продукт

1. **Бот на Маке.** Телеграм-бот ([fivol/reels-bot](https://github.com/fivol/reels-bot)) на подписке Claude владельца придумывал и монтировал рилсы для медиа My Gudauri. Мак засыпал, бот падал (старый pid-файл), поэтому бота перенесли на сервер.
2. **Сервер.** Перебрали Oracle Free, Railway и другие: бесплатные и западные просят иностранную карту, а Claude не работает с российских адресов. Выбрали Timeweb Cloud в Амстердаме с оплатой в рублях. Claude там входит по токену `claude setup-token`, он действует год.
3. **Веб-версия как демо.** Сначала это был просто чат. Потом появилась студия: чат на каждый выпуск, версии видео, файлы и материалы, правила и бриф, дизайн-система, доступ и приглашения.
4. **Команда.** Приглашения работают и в вебе, и в Телеграме, потому что список людей один (`access.json`). В боте с Claude одновременно говорит один человек, остальные ждут в очереди.
5. **Пакет для других.** Публичный репозиторий плюс сайт-установщик на GitHub Pages: человек отдаёт своему Claude фразу, и тот ставит бота по `SETUP.md`.
6. **Совместная разработка.** Справочник `handbook/`, задачи на GitHub, ветка и pull request на каждую задачу, общий стенд.

## Как пришли к интерфейсу

Холст на claude.ai (доступ даёт владелец) хранит всю историю досок:

- **Черновики** (страницы «Черновик N»): первый веб-интерфейс, сценарии UX (U1–U9), рабочие места (W1–W11), оболочка вокруг чата (S1–S10), структура разделов (P1–P9), серии (C0–C10). Здесь только история, по ним не строим.
- **Итог** (★): «Вся система на одном листе», «Интерфейс: итог» F0–F10, «Команда» T0–T★ с экранами по ролям A/H/E/S/R.

Повороты, к которым пришли по ходу работы:
- «Всё должно крутиться вокруг чата». Любая единица контента — это чат и панель справа, как у бота, только с экраном. Отдельные «страницы-формы» отбросили.
- Интерфейс разделён на три раздела: Работа · План · Проект. Вместо них были длинные меню из 8–10 пунктов, это отбросили.
- Каскад настроек: проект → канал → формат → рубрика → серия → выпуск. Ниже по каскаду правила строже, замок 🔒 запрещает их переопределять. Каскад появился, чтобы каждый выпуск-чат сам знал свои правила и не приходилось повторять их в каждом чате.
- Серии вместо роликов с нуля. Так уже получилось само собой на роликах с ценами (02 → 10 → 13). Оценка: около 2/3 контента ложится в серии, а мемы и новости остаются разовыми.
- Ролей три (редактор, автор, ведущий) вместо шести. Авторам (учителям) не нужно ставить приложение, им хватает бота.

## Что пробовали и отбросили

- Агент студии в режиме «без вопросов» (`--dangerously-skip-permissions`). Страница в интернете не должна давать произвольный доступ к серверу, поэтому теперь у агента список разрешений и отдельный пользователь на сервере.
- Хранить все версии целиком: диск сервера 30 ГБ. Теперь хранится так: текущая версия целиком, прошлая — лёгкой копией, более старые — кадр и снимок кода.
- Приглашение, которое срабатывает по одному открытию ссылки. Мессенджеры открывают ссылку сами ради предпросмотра и «съедали» приглашение. Теперь по ссылке открывается кнопка «Войти», а приглашение срабатывает по её нажатию.
- Экран «начинаю урок» перед каждым уроком, хроники, которые «ждут сами», автосборка рилсов из случайных видео, свой видеоредактор, автопубликация без проверки Meta. Всё это отложено или отброшено, подробнее в `PRODUCT.md` («Чего не делаем»).

## Открытые вопросы

- **Постоянный адрес.** Ссылки студии и стенда — временные адреса Cloudflare, они меняются при перезапуске. Нужен свой домен с именованным туннелем.
- **Стенд на подписке владельца.** Агент стенда тратит лимиты Claude владельца. Если станет тесно, нужен отдельный токен.
- **Равные права в GitHub.** В личном репозитории второму человеку можно дать только запись. Равные права дадут организация GitHub и перенос репозитория в неё.
- **Пилоты.** Медиа My Gudauri (один автор-ведущий) и школа (учителя, редактор, ведущий). Этап 1 считается готовым, когда пилотная команда неделю публикует только через студию.
