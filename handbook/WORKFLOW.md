# Как работаем

## Кто есть кто в разработке

- **Владелец продукта** — Миша: решает, что делаем, принимает работу, выкладывает на сервер.
- **Дизайнер** — рисует и правит доски на холсте, отвечает на вопросы по интерфейсу в задачах.
- **Разработчик** — делает задачи в своей ветке со своим Claude Code и присылает pull request.

У каждого своя подписка Claude. Общие только репозиторий, задачи и холст.

## Первый день в команде

1. Принять приглашение в репозиторий (письмо от GitHub или github.com/mixa-lll/reels-studio/invitations).
2. Поставить приложение Claude (claude.ai/download, нужна своя подписка Pro или Max) и открыть вкладку **Code**.
3. Выбрать любую папку, например «Документы», и написать: «Склонируй https://github.com/mixa-lll/reels-studio, открой этот проект и подключи мой GitHub, чтобы я мог отправлять изменения». Claude скачает код, поможет войти в GitHub и перейдёт в папку проекта.
4. Прочитать `handbook/HISTORY.md` — что уже придумано и отброшено (или попросить Claude пересказать).
5. Написать: «возьми задачу #3» — это запуск бота и студии у себя с тестовым ботом.

Без приложения, в терминале: `git clone https://github.com/mixa-lll/reels-studio && cd reels-studio && claude`.

## Путь задачи

1. **Задача** в Issues: что сделать, ссылки на доски холста, как проверить. Без проверки задача не начинается.
2. **Ветка** от `main`: `<номер>-коротко` (например `12-inbox-variants`).
3. **Claude Code** в этой ветке: «возьми задачу #12». Claude сам читает `AGENTS.md` и `handbook/`.
4. **Проверка у себя**: свой тестовый Телеграм-бот и своя студия (ниже). Скриншот или запись экрана — в pull request.
5. **Pull request** по шаблону → ревью владельца или второго разработчика → слияние в `main`.
6. **Стенд** через пару минут сам показывает слитое — там смотрим вместе (ссылку даёт владелец).
7. **Выкладка** — только владелец: `reels-deploy` на сервере (см. ARCHITECTURE.md).

Одна задача — один pull request. Решение, принятое по ходу, — строка в `handbook/DECISIONS.md` в том же pull request.

## Что сказать своему Claude

| Нужно | Фраза |
|---|---|
| Взять задачу | «возьми задачу #12» — Claude сделает ветку, прочитает задачу и доски |
| Посмотреть результат | «запусти бота и студию и открой студию в браузере» |
| Отдать на проверку | «сделай pull request по задаче #12 со скриншотом» |
| Поправить по ревью | «посмотри комментарии в pull request и поправь» |
| Забрать свежие изменения команды | «подтяни свежий main» |

## Дизайн

- Холст на claude.ai — источник правды для интерфейса. Доступ выдаёт владелец через Share.
- Утверждённые страницы помечены ★. Страницы «Черновик N» — история, по ним не строим.
- Новая идея — новая доска рядом или комментарий на холсте; правка утверждённой доски — только с владельцем.
- Задача на интерфейс ссылается на доски по коду: F3, E1, T★.

## Поднять у себя

1. Создать тестового бота в @BotFather (не рабочего!).
2. В Claude Code открыть свою копию репозитория и написать: «Set up this repo for development — follow SETUP.md, with my test bot». Claude спросит ключ бота и включит веб-студию.
3. Студия: `http://localhost:8080/?k=<WEB_KEY из .env>`.

Данные (`projects/`, `data/`, `.env`, `web/data/`) в репозиторий не попадают никогда.

## Нельзя

- Трогать рабочий бот и сервер владельца, коммитить ключи и личные данные.
- Делать в одном pull request несколько задач или незаказанный рефакторинг.
- Строить по черновым страницам холста.
