# Основа без лишнего: перенос с холста по кускам

Холст: страница «★ Основа без лишнего» (доски L0–L25). Здесь записано, в каком порядке её переносим в студию и как меняются данные. Один кусок = одна ветка `lean-N-…` и один PR в `main`. На прод выкладываем только после «да» Миши. Бота (`bot/*`, `REELS.md`) не трогаем: его прорабатывают отдельно, и он должен работать как раньше.

## Главная мысль

Любой выпуск — это **одна единица одного формата**. Она проходит пять этапов:

| Этап | `stage` | Что происходит |
|---|---|---|
| Идея | `idea` | концепция: о чём, крючок, ход, рубрика, формат, дата. Снимать ещё ничего не надо |
| Материал | `material` | Claude говорит, что снять; человек досылает, пункты закрываются |
| Сборка | `build` | Claude монтирует или пишет, версии, правки словами |
| Готово | `ready` | «Как увидят», проверка, одобрено и ждёт своего дня |
| Вышло | `published` | выложено |

- План — это идеи на датах. Claude может расписать их сам («Расписать идеи»).
- Рубрика — простая группа похожих выпусков: название, цвет, формула, обычный формат и день.
- Один материал на три формата — это три отдельных выпуска. Их связывает только общая группа `group`.

## Как сейчас хранятся данные (не ломаем)

- **Рилс** — папка `projects/<p>/reels/<NN-slug>/`: README, `scenes.json`, `publish.json`, `versions/vN/`. Статус берётся из раздела `ideas.md`, где лежит его запись (In work / In review / Done / Published). `ideas.md` ведут бот и Claude по `REELS.md`.
- **Пост, карусель, текст в Телеграм** — папка `posts/<NN-slug>/post.json` (`kind: text | photo | carousel`). Этап считается в `stageOf()` (`web/posts.mjs`).
- **Дата и рубрика** — `plan.json` (`at`, `rubric` по ключам `reel:<id>` и `post:<id>`).
- **Рубрики, площадки, ритм** — `strategy.json`.

## Новая модель: `projects/<p>/items.json`

Это один список единиц контента, из него рисуются Выпуски, План и Сегодня. Папки рилсов и постов остаются как есть: элемент списка на них ссылается.

```json
{"v": 1, "items": [
  {"id": "i-7f3a", "format": "reel", "title": "Первый снег",
   "stage": "build", "rubric": "now", "at": "2026-11-07T18:00", "platforms": ["ig-ru", "ig-en"],
   "group": "g-snow", "ref": {"kind": "reel", "id": "16-first-snow"},
   "idea": {"about": "…", "hook": "…", "flow": ["…", "…"]},
   "need": [{"text": "Табло подъёмника", "have": "sources/IMG_2.jpg"}],
   "by": "Claude", "created": 1793790000000, "stageAt": 1793790000000}
]}
```

- `format`: `reel | post | carousel | telegram | story`. `post` — это `kind: photo`, `telegram` — `kind: text`. Формат `story` пока только для предпросмотра.
- `ref` указывает на папку рилса или поста. Пока материала нет, `ref` не задан: тогда это чистая идея.
- `rubric` — `id` из `strategy.json`.
- `need` — что снять или найти. Для рилса берётся из `scenes.json` (`need` / `have` / `status`).

### Этап считается сам, двигается вперёд

Сервер выводит этап из файлов и сохраняет его, если вывод дальше сохранённого:

- **рилс**: нет папки → `idea`; есть папка, но нет версий, или в `scenes.json` есть «нужно» → `material`; есть версии → `build`; запись в разделе Done → `ready`; в разделе Published → `published`;
- **пост**: в `post.json` нет фото, а для фото-поста не хватает исходников → `material`; `stageOf` даёт text / struct / slides → `build`; publish → `ready`; done → `published`.

Ручное «Вернуть в сборку» держится, пока не появится новая версия.

### Миграция

Скрипт `scripts/lean-migrate.mjs <project> [--dry]` один раз собирает `items.json`:
- из всех рилсов и постов;
- из `plan.json` — даты и рубрики;
- из групп `Owner's ideas` и `My ideas` в `ideas.md` — идеи без папки.

Старые файлы скрипт не меняет, копия `plan.json` ложится в `plan.json.bak`. Повторный запуск ничего не дублирует: элементы сверяются по `ref` и названию идеи. После миграции веб пишет дату и рубрику и в `items.json`, и в `plan.json`: агент и бот продолжают читать `plan.json`.

## Сделано

- **Кусок 1 · Модель.** `web/items.mjs`, API `GET /api/items`, `POST /api/items/set`, `POST /api/items/new`, скрипт `scripts/lean-migrate.mjs`. `/api/plan/set` и `items.json` держат дату и рубрику согласованными. На копии `projects/main`: 82 единицы (17 выпусков, 65 предложений из `ideas.md`), повторный запуск ничего не добавляет. Пока не связано: если Claude делает рилс из взятой идеи, появится второй элемент. Связь идея → папка появится в куске 4, когда этап «Материал» начнётся из веба.

- **Кусок 2 · Колонка.** В колонке Сегодня · Выпуски · План · Память, внизу Настройки. Входящие и Задания появляются только у команды, как раньше. Память пока собирает старые вкладки: О проекте (бриф), Голос и стиль, Правила, Дизайн, Файлы. В Настройках остались Команда и Тестовые аккаунты; старые адреса `#/settings/voice|rules|ds|files` ведут в Память. Стратегия, Идеи и рубрики открываются из Плана («Площадки и рубрики») и через поиск ⌘K.

## Как проверяем

Ветка запускается из своей рабочей папки на отдельном порту (`:8091`) с **копией** `projects/main`. Живая студия на `:8090` и её данные не трогаем. Отчёт после каждого куска — несколько строк по-русски со снимком экрана, потом вопрос, идти ли дальше.
