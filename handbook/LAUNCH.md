# Запуск: первый заказчик и первые деньги

Черновик плана, 28.10.2026. Цифры цен — в скобках `[₽]`: их решают Миша и Сева. Технические вводные по школе — техплан «Автоматизация SMM Талантвилль» (21.10).

## Главное условие: для школы в России нейросеть — не Claude

Anthropic не обслуживает Россию и компании со штаб-квартирой в РФ, в том числе через зарубежный сервер. Сейчас вся студия работает через Claude Code: бот передаёт каждое сообщение агенту, агент пишет код ролика. Для первого заказчика так нельзя, и обходить это мы не будем.

Значит, этап 1 строим так, чтобы нейросеть была сменной деталью:

- **Провайдер нейросети** — один модуль `llm.mjs` с тремя реализациями: GigaChat (для РФ), YandexGPT (запасной), Claude (для заказчиков вне РФ и для разработки). Проект выбирает провайдера в настройках.
- **Нейросеть отвечает данными, а не кодом.** Она раскладывает материал, пишет тексты вариантов и правки в виде JSON по схеме. Всё остальное делает наш код: шаблоны постов и слайдов, шаблоны роликов (Т1, `reel.json`), рендер Remotion, ffmpeg. Это и проще для GigaChat, и предсказуемее для нас.
- Claude Code остаётся инструментом разработки и вариантом «Про» для заказчиков, где он доступен.

## Что продаём на этапе 1

Минимум, за который школа платит: **посты из фото учителей и ролики по шаблонам, всё через Телеграм**.

1. Учитель скидывает фото, видео, голосовое в бот → «Понял так» → один вопрос, если без него нельзя.
2. Система делает 2–3 варианта поста (Телеграм длинный, Instagram короткий, VK) и карусель по 5 шаблонам слайдов.
3. Редактор выбирает вариант в боте или мини-приложении → в план на дату → публикация (Телеграм — сами, Instagram — Graph API, VK — через посредника или вручную).
4. Ролики: материал → шаблон рубрики → черновик → правки комментариями (SE1–SE5) → «Собрать vN». Правка — изменение данных шаблона (текст, порядок и длина сцен, обрезка куска), без переписывания кода.
5. Автору — «Ваш урок вышел».

Не входит в этап 1: статистика и выводы, свободный монтаж, автопостинг трендовых рилсов (звук Instagram через API не добавить), MAX.

## Режимы, тарифы и уровни доступа

Три независимые оси. Сейчас в коде есть только третья.

**1. Режим — как устроен заказчик.** Меняет интерфейс, а не цену.

| Режим | Кто | Что видно |
|---|---|---|
| Один | эксперт, блогер, маленький бизнес | нет Входящих, заданий людям и согласования |
| Команда | школа, клиника, студия | участники, задания, входящие, согласующий по ссылке |
| Агентство | SMM-специалист с несколькими клиентами | несколько проектов, переключатель, отчёт по проектам |

**2. Тариф — какие функции включены и сколько.**

| Функция | Посты | Посты + видео | Команда | Агентство |
|---|---|---|---|---|
| Посты, карусели, план | ✓ | ✓ | ✓ | ✓ |
| Ролики по шаблонам, редактор | — | ✓ | ✓ | ✓ |
| Съёмка себя с суфлёром | — | ✓ | ✓ | ✓ |
| Участники, задания, входящие | — | — | ✓ | ✓ |
| Согласующий по ссылке | — | — | ✓ | ✓ |
| Проектов | 1 | 1 | 1 | до [N] |
| Публикаций в месяц | [N] | [N] | [N] | [N] на проект |
| Цена в месяц | [₽] | [₽] | [₽] | [₽] |

**3. Роли в проекте** — уже есть (ROADMAP, этап 5): редактор, участник, владелец (галочка), замещающий, согласующий (ссылка), «в кадре», «сам собирает». Плюс тестовые профили для проверки (сделано, см. ниже).

**Как это сделать в коде.** Один файл `plans.json`: тариф → список функций и лимиты. В настройках проекта `mode` и `plan`. Одна проверка `can(project, feature)` в сервере, мини-приложении и боте; интерфейс прячет то, что выключено, и говорит «доступно в тарифе …». Лимиты считаем по журналу публикаций.

## Новый диалоговый бот

**Почему переписываем.** Сейчас бот — прокладка к агенту: любое сообщение становится ходом Claude Code. Отсюда долгие ответы, непредсказуемый текст, нельзя подключить GigaChat, нет понятных состояний диалога. Экраны переписки на холсте («Черновик 8», A0–A12, E7, E11–E13, H7–H12) уже рисуют другой бот.

**Каким будет.**

- **Сценарии вместо свободного чата.** Каждая роль — свой набор: участник (Скинуть → «Понял так» → вопрос → «вышло», Что снять, Моё, Профиль), редактор (варианты пачкой, согласование, «не вышло», отзыв согласия), съёмка (задание → мини-приложение). Состояние диалога хранится явно: `chats/<id>.json` со сценарием и шагом.
- **Только то, что умеет Телеграм.** Кнопки под сообщением, нижняя клавиатура, команды, мини-приложение. Выбор — правкой своего сообщения, без потока ответов.
- **Нейросеть — только там, где нужна.** Разобрать материал, написать варианты, применить правку. Через `llm.mjs`, ответ — JSON по схеме, с проверкой.
- **Правила общения в коде:** тихие часы, не больше 3 сообщений в день участнику, пачки для редактора, «молчание = верно».
- **Локальный Bot API** с первого дня: файлы до 2 ГБ вместо 20 МБ.
- Старый бот с агентом остаётся режимом «Про» для владельцев с Claude.

## Как проверяем: тестовые профили

В мини-приложении у владельца: Профиль › Тестовые профили. Создать профиль нужной роли (участник, «в кадре», «сам собирает», замещающий, редактор), войти под ним одной кнопкой, вернуться кнопкой «Выйти» в синей полосе сверху. «Удалить» стирает профиль и всё, что он успел сделать: его задания и записи, загруженные файлы, начатые ролики, правки текста, настройки и строки журнала. Данные настоящих людей не трогает. Боевой аккаунт школы на тестах не используем.
